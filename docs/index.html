Documentación del Proyecto – Control de Carro con HTTP + MQTT

Descripción General

Este ESP32 expone un servidor HTTP con dos endpoints principales:

  • /move — Recibe instrucciones de movimiento.
  • /status — Verifica si el servidor está disponible.

Cada instrucción enviada al endpoint /move se publica además en un broker MQTT en el tema configurado.

Endpoint: /status

Método: GET

Devuelve un mensaje indicando que el servidor está funcionando.

{
  "status": "OK",
  "message": "Servidor en ejecución"
}

Endpoint: /move

Método: POST

Body esperado (JSON)

{
  "direction": "forward | backward | left | right",
  "speed": 0-255,
  "duration": 1-5
}

Ejemplo:

{
  "direction": "forward",
  "speed": 150,
  "duration": 3
}

Respuesta:

{
  "message": "Instrucción recibida",
  "client_ip": "192.168.1.50"
}

MQTT

Cada instrucción enviada al endpoint /move se publica en un servidor MQTT con el siguiente payload: 

{
  "direction": "forward",
  "speed": 150,
  "duration": 3,
  "client_ip": "192.168.1.50"
}

El ESP32 envía el mensaje al tema configurado en el código fuente, por ejemplo:

esp32/car/move

Archivos incluidos en la carpeta docs/

  • index.html → este archivo
  • openAPI.yaml → definición OpenAPI de los endpoints
  • postman_collection.json → colección Postman para pruebas
  • sequence_diagram.mmd (opcional) → diagrama de secuencia en Mermaid
